# MemoryDeck 路线图

> 记录 v1.0.0 之后可以往哪些方向走。
> 每条都标了**为什么值得做**、**大概造价**、**风险**。
> 不是承诺，是候选清单。

---

## 当前的边界（先说清楚）

v1.0.0 解决的是**一个**具体问题：

> 用 Markdown 维护"跟 AI 协作的长期记忆"时，人得手改表格、手维护 ID、
> 手同步摘要给 AI。改多了破表，改忘了 AI 读不到。

在这个范围内它是完整闭环：界面点一下 → 文件变 → AI 下一轮读到。

**超出这个范围，它现在只是个普通表格编辑器。** 下面这些是缺口。

| 缺口 | 现状 |
| --- | --- |
| 快 | 想记一条，得先找到窗口 → `Ctrl+N` → 填 → 保存。**打断了当前工作** |
| 稳 | 同一目录开两个实例会互相覆盖，没有锁 |
| 可逆 | 只有删除前备份，**没有撤销**；误改要手工翻备份 |
| 可查 | 只有子串匹配，条目上百条后基本靠肉眼 |
| 可迁 | 只能存本地；换机器要手动拷目录 |
| 可关联 | 一条记忆就是一个孤立行，没有标签、没有互链 |
| 可信 | 没有校验，文件被外部工具改坏了只能靠 `--repair` 猜 |

## 第一梯队：磨掉日常摩擦（收益最直接）

### 1. 全局热键 + 快速录入浮窗

**问题**：记一条记忆要切窗口，这一下打断往往就懒得记了。**记忆工具最大的敌人是"懒得打开"。**

**做法**
- `RegisterHotKey` 注册全局快捷键（默认 `Ctrl+Alt+M`，可配置）
- 按下弹出无边框小窗，只有「内容」一个输入框 + 类别下拉
- `Enter` 保存并关闭，`Esc` 取消，保存后托盘气泡提示
- 焦点丢失自动隐藏

**造价**：约 200 行。`RegisterHotKey` + 一个精简 Form。
**风险**：热键冲突需要给用户改键入口。

### 2. 托盘常驻 + 开机自启

**问题**：窗口关了就不在，等于每次都要重新启动。

**做法**
- `NotifyIcon` 常驻托盘，左键呼出主窗，右键菜单：新建 / 打开数据目录 / 退出
- 关闭按钮改为最小化到托盘（首次提示一次，可设置里关掉）
- 自启走注册表 `HKCU\...\Run`，或放快捷方式到启动目录（**不用管理员权限**）

**造价**：约 150 行。
**风险**：托盘程序容易被用户误以为"关不掉"，要有明确的退出入口。

### 3. 撤销 / 操作历史

**问题**：现在误删只能靠翻 `.memory-deck/backups` 里的时间戳文件，**体验很差**。

**做法**
- 内存里维护一个操作栈（`Add` / `Update` / `Remove` 的记录）
- `Ctrl+Z` 撤销上一次，支持连续撤销到本次会话开始
- 界面状态栏显示"可撤销 N 步"
- 跨会话的撤销仍靠备份文件，但提供**图形化的备份浏览与恢复**：
  列出备份时间线，点一条看 diff，一键恢复

**造价**：约 250 行（含备份恢复界面）。
**风险**：撤销要小心与外部修改的交互（外部改了文件后，旧操作栈可能失效）。

### 4. 多选与批量操作

**问题**：条目多了以后，逐条改类别、逐条删，非常烦。

**做法**
- 表格开启 `MultiSelect`
- 支持：批量删除、批量改类别、批量导出选中
- 加「全选 / 反选」与 `Ctrl+A`

**造价**：约 150 行。
**风险**：批量删除要更严格的二次确认（显示将删除的条目数）。

## 第二梯队：让数据变大以后还能用

### 5. 结构化字段：标签 + 重要性 + 有效期

**问题**：现在一条记忆只有 `类别 / 内容 / 来源 / 时间`。类别是单一维度，没法交叉检索。

**做法**
- 内容里加内联标签语法 `#标签`，解析时提取为独立列
- 加「重要性」（1–5 星）与「有效期至」（到期条目在界面上高亮）
- 过滤器支持标签多选 + 重要性区间

**造价**：约 300 行（含解析、显示、过滤、旧的 5 列表格兼容）。
**风险**：改表格结构会影响已存在的 `MEMORY.md`，必须保持向后兼容——
新列缺失时按默认值处理，写入时保留用户原有的列集合。

### 6. 全文检索增强

**问题**：子串匹配在几百条时基本不可用。

**做法**
- 先做**加权子串**（ID 完全匹配 > 类别 > 内容），不需要索引
- 再做增量倒排索引（内存里维护 `词 → 条目ID 集合`），启动时从文件构建
- 支持 `类别:身份 学生` 这样的字段限定语法
- 搜索结果高亮匹配片段

**造价**：加权约 100 行；倒排索引约 300 行。
**风险**：条目量在千级内，加权子串其实就够了，倒排索引可能是过度设计。
**建议**：先做加权，等真的卡了再做索引。

### 7. 多文件 / 分库

**问题**：所有记忆挤在一个表里，久了会乱（比如工作与个人混在一起）。

**做法**
- 数据目录支持多个 `.md` 记忆文件，界面左侧加文件列表
- 全局搜索可跨文件
- `AGENTS.md` 摘要只聚合"主库"，或按文件分别生成摘要区

**造价**：约 400 行（改动面较大，涉及 StorageConfig 与 Repository 抽象）。
**风险**：会显著复杂化"数据源唯一"这个简单模型，**要谨慎**。

## 第三梯队：稳固与工程化

### 8. 单实例锁

**问题**：现在开两个实例会互相覆盖。这是**数据安全**问题，不是体验问题。

**做法**
- 命名 Mutex（`Global\MemoryDeck-<数据目录哈希>`）
- 第二个实例启动时激活已有窗口并退出
- 或允许只读模式打开

**造价**：约 80 行。
**优先级**：**高**。这是当前最应该补的稳定性缺口。

### 9. 数据校验与自愈增强

**做法**
- 启动时校验：ID 唯一性、必填字段非空、时间格式、类别非空
- 发现异常在界面上标红并给出修复建议，而不是静默修正
- 保留 `--repair` 作为自动修复入口

**造价**：约 200 行。
**风险**：校验规则过严会拒绝合法的历史数据，必须"警告但不阻断"。

### 10. 导入 / 导出

**做法**
- 导出 `JSON` / `CSV`（供其他工具消费）
- 导入时做字段映射预览，避免脏数据直接落盘
- 导出当前筛选结果

**造价**：约 250 行。

## 明确**不做**的事

| 不做 | 理由 |
| --- | --- |
| 云同步 / 账号系统 | 一旦引入服务端，就背离"Markdown 即数据源、无依赖"的核心取舍 |
| 数据库（SQLite 等） | 手改友好、Git 友好、AI 直接可读，这三条比查询性能重要得多 |
| 富文本编辑器 | 数据源是 Markdown 文本，所见即所得会引入转义地狱 |
| 跨平台 | 界面基于 WinForms，重写成本远超收益 |
| 加密 | 会让人误以为安全；真要保密应该用磁盘加密或密码管理器 |

---

## 建议的实施顺序

```
第 1 步  单实例锁（数据安全，成本最低，收益最高）
第 2 步  全局热键 + 快速录入（直接提升"愿不愿意记"）
第 3 步  托盘常驻 + 开机自启（配合上一步形成"随手可记"）
第 4 步  撤销 + 备份图形化恢复（把"可逆"补齐）
第 5 步  多选批量操作
第 6 步  加权搜索
第 7 步  标签 / 重要性（改动数据模型，需谨慎设计兼容）
```

前 4 步做完，它就从"一个好用的查看器"变成"一个会日常使用的工具"。

---

## 每次改动都要守住的底线

这些是 v1.0.0 已经立住的约定，**任何迭代都不能破坏**：

1. **`MEMORY.md` 是唯一数据源**——不引入影子存储
2. **手写区域零侵入**——表格前后的内容必须原样保留（有 `Test13` 守着）
3. **写入幂等**——反复读写同一文件，结果字节级一致
4. **写前必备份**——任何落盘动作前先备份
5. **界面回调必须过异常护栏**——未捕获的 UI 异常会直接杀进程
6. **新功能必须带自检**——尤其是界面路径，`Test12` 那种冒烟覆盖不可省

> 第 5、6 条是拿三个真实崩溃换来的教训。忘了它们就会重蹈覆辙。
